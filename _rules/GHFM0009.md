## Trigger

A top-level front-matter key is not declared by any schema that governs the
document. The known set is the union of four sources: the base schema, the
Dublin Core relations set, the governance overlay, and the per-type schema the
document's folder dispatches to. Nested keys are not checked by this rule; only
the top level is.

The three agent-tool keys `name`, `globs` and `instructions` are deliberately
skipped here, because `GHFM0006` already reports them with better advice.

## Why the rule exists

An unknown key is nearly always one of two things. A typo, in which case the
field you meant to set is not set and nothing told you. Or vocabulary invented
locally, in which case the key is real to its author and invisible to every
consumer: no schema validates it, no dashboard reads it, no register indexes
it. Both cases look identical in a diff, and both fail silently. This rule is
the only thing that distinguishes "I set that field" from "I set a field".

## Fix

1. Check the spelling first. `lifecyle`, `referenes` and `isPartof` are the
   three most common, and the fix is a character.
2. If the key is spelled correctly but still unknown, check that the document
   is in the folder whose schema declares it. `status` is declared for plans,
   not for every document class.
3. If the key is genuinely new vocabulary, take it through the schema-change
   path in the front-matter standards spec (design-038) section 7. That is a
   TypeSpec model change and a schema regeneration, and it is deliberately not
   something a single document can do on its own.
4. If the value was informational and nothing reads it, move it into the body
   as prose. Front matter is a contract; the body is for everything else.

**Quotable fix.** Paste this into a review comment:

> **GHFM0009 (unknown-key).** This top-level front-matter key is not declared

> schema this document's folder dispatches to, so nothing reads it. Check the

> schema-change path rather than in this document; if it is informational,
> move it into the body.

## Enforcement

Default severity is `warning`, so the finding annotates a pull request without
blocking it. The rule is active from enforcement phase A, per the front-matter
standards spec (design-038) section 6.2, and no phase promotes it to `error`.
