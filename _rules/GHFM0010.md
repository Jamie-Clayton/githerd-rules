# GHFM0010: metrics-key-shape

The metrics-contract decision record (adr-054) D3 requires every key in a metrics mapping to match ^[a-z][a-z0-9_]*$. JSON Schema cannot express this, because the metrics property has no properties block and additionalProperties constrains values rather than key names, so the validator enforces it directly. Documents with lifecycle archived are exempt as accepted permanent legacy. Rename the key, or run the metrics-key rename script.

## Trigger

A key inside the document's `metrics` mapping does not match
`^[a-z][a-z0-9_]*$`. In practice that means a dotted key such as
`initiative.value.score`, a hyphenated key such as `time-criticality`, or a
camelCase key such as `wsjfScore`. The match is case-sensitive on purpose:
a case-insensitive check would wave `wsjfScore` through.

Documents whose `lifecycle` is `archived` are exempt. Archived documents are
accepted permanent legacy, and archive semantics say do not rewrite history.

## Why the rule exists

The metrics contract requires flat lowercase snake_case keys so that a metrics
mapping is directly addressable by every consumer: a JSON Pointer, a dashboard
column, a register column, and a SQL identifier all work without escaping. A
dotted key reads as a nested path to some consumers and as a flat string to
others, and the two disagree about how many metrics the document has.

The check lives in the validator rather than in a JSON Schema because JSON
Schema cannot express it. The `metrics` property has no `properties` block, and
`additionalProperties` constrains values rather than key names, so there is no
schema keyword that says "the key must look like this". Doing it in code is not
a shortcut here; it is the only place the constraint fits.

## Fix

1. Rename the key to flat lowercase snake_case. The diagnostic message carries
   the canonical name it expects, so you rarely have to work it out.
2. For the five WSJF axes the canonical names are fixed:
   `initiative.value.score` becomes `value`, `initiative.time-criticality`
   becomes `time_criticality`, `initiative.risk-reduction` becomes
   `risk_reduction`, `initiative.effort.points` becomes `effort`, and
   `initiative.wsjf.score` becomes `wsjf_score`.
3. For anything else the mechanical rule is: drop an `initiative.` prefix, turn
   `.` and `-` into `_`, and lowercase the result.
4. To fix a batch rather than one document, run the sweep that owns this
   rename: `pwsh -NoProfile -File scripts/Rename-FrontMatterMetricsKey.ps1`.
5. Do not rename keys in an `archived` document. It is exempt, and rewriting it
   changes a historical record for no gain.

## Example (violating)

Copied verbatim from `tests/fixtures/front-matter/ghfm0010-triggering.md`, so
it is executable against the validator rather than merely illustrative. Two
keys, two diagnostics: the rule reports once per offending key.

````markdown
---
type: initiative
id: init-hm010-fail
metrics:
  initiative.value.score: 8
  initiative.time-criticality: 5
---

# Dotted Metrics Keys

Neither key is flat lowercase snake_case, so GHFM0010 (metrics-key-shape)
fires once per key.
````

## Example (compliant)

````markdown
Both keys match `^[a-z][a-z0-9_]*$`, so GHFM0010 stays quiet.
````
