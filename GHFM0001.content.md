## Trigger

The validator reads the first line of the file and finds no `---` fence, so
there is no YAML front-matter block to parse. A block that starts on line two
or later does not count: the opening fence must be the first line, after an
optional UTF-8 byte-order mark.

## Why the rule exists

Front matter is how a document declares what it is. Without it the harness
cannot dispatch a schema, cannot place the document in the graph, and cannot
resolve any relation pointing at it. The file is still readable by a human and
completely invisible to every tool. That is a silent failure, and this rule is
the noise that replaces it.

## Fix

1. Add a `---` fence as the very first line of the file.
2. Declare the fields the schema for the file's folder requires. A document
   under `docs/specs/` dispatches to the design-spec schema, one under
   `docs/architecture/ADRs/` to the decision-record schema, and anything
   outside a mapped folder to the permissive base schema.
3. Close the block with a second `---` fence before the body.
4. Re-run the validator over the single file to confirm the block parses:
   `pwsh -NoProfile -File scripts/Test-HarnessMetadata.ps1 -Path <file>`.

**Quotable fix.** Paste this into a review comment:

> **GHFM0001 (missing-front-matter).** This file has no YAML front-matter
> block, so no metadata contract is dispatched for it and it does not appear
> in the document graph. Add a `---` fenced block as the first line of the
> file declaring at least `type`, `id` and `date`, and close it with a second
> `---` before the body.

## Example (violating)

Copied verbatim from `tests/fixtures/front-matter/ghfm0001-triggering.md`, so
the example is executable against the validator.

````markdown
# No Front Matter

This file has no YAML front-matter block. GHFM0001 (missing-front-matter) must fire.
````

## Example (compliant)

Copied verbatim from `tests/fixtures/front-matter/ghfm0001-passing.md`.

````markdown
---
type: spec
id: spec-hm001-pass
date: 2026-04-20
---

# Has Front Matter
````

## Enforcement

Default severity is `warning`, so the finding annotates a pull request without
blocking it. The front-matter standards spec (design-038) section 6.2 escalates
this rule to `error` in enforcement phase B, and only for files the diff shows
as new. Existing untagged documents are not retro-blocked.
