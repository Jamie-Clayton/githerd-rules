## Trigger

The front-matter block was found and fenced correctly, but the YAML parser
raised while reading it. Unterminated flow sequences (`[a, b`), unterminated
quotes, tab characters used for indentation, and a mapping value that starts a
new mapping at the wrong indent are the four that account for almost every
occurrence. The diagnostic carries the parser's own line and column where the
parser reports them.

## Why the rule exists

A parse failure is total, not partial. Nothing downstream of the parse runs for
this file: no schema validation, no cross-field lint, no graph edge. Every
other rule on this site is silent about a file that fails here, which is why
this one is an `error` and not a `warning`. A document that cannot be parsed is
a document the harness cannot see.

## Fix

1. Read the reported line and column. The parser points at where it gave up,
   which is usually one line past where the mistake is.
2. Check the four usual causes in order: an unclosed `[` or `{`, an unclosed
   quote, a literal tab used for indentation, and a value containing an
   unquoted `: ` sequence.
3. Quote any value containing `:`, `#`, `[`, `{`, `*`, `&` or a leading `%`.
4. Re-run the validator over the single file. The rule is satisfied when the
   block parses; whether it then satisfies its schema is a separate finding.

**Quotable fix.** Paste this into a review comment:

> **GHFM0002 (yaml-parse-error).** The front-matter block does not parse, so
> none of this document's metadata is readable and every other front-matter
> check is skipped for it. Check the reported line for an unterminated
> bracket or quote, a tab used for indentation, or an unquoted value
> containing a colon, and quote the value if in doubt.

## Enforcement

Default severity is `error`, and it blocks a pull request from enforcement
phase A onward, per the front-matter standards spec (design-038) section 6.2.
This is one of the four rules that has always blocked; the rename did not
change which rules block or when.
