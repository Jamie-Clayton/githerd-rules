## Trigger

The repository's subject policy, kept in the subject vocabulary register at
`extensions["githerd:subjectPolicy"]`, gives each document type an `allowed`
list of concepts (`ability:traceability`) or whole schemes (`ability:*`), and
a `mode`. The rule reports, on the line the subject sits on:

- A subject that resolves to an active concept the type's `allowed` list does
  not name, in either mode.
- For a type whose `mode` is `closed`, a subject that is not a concept at all:
  a plain keyword such as `lineage`, or a token whose prefix the register
  does not declare, such as `topic:anything`. When the keyword is a label or
  legacy tag of one concept, the message names that concept.

A prefixed subject that does not resolve, or names a retired concept, is left
to GHFM0015, so one subject never raises both rules.

A document type without its own entry uses the policy's `default`. Without a
policy, the built-in default applies: open, and every declared scheme
allowed, so the rule is silent until a repository writes a policy. A policy
that fails its schema, SP001 or SP002 is ignored whole for the same default;
the rule reports that once per run, against the register.

## Why the rule exists

A subject policy is how a repository says which concepts belong on which
documents: decision records about governance, plans about delivery. Without
enforcement it is a wish list. The rule keeps the dashboard facet and the
roll-ups meaningful by catching a concept that wandered onto the wrong kind
of document, and, where a type is closed, a keyword that should have been a
concept.

The policy is resolved by `scripts/Resolve-SubjectPolicy.ps1`, the same
resolver the adopter guard `scripts/Test-SubjectPolicy.ps1` uses, so the rule
and the guard cannot disagree.

## Fix

1. Use a concept the type allows. `githerd_subject_policy` lists them.
2. For a closed type, replace the keyword with the concept the message names,
   or remove it.
3. If the document is right and the policy is too narrow, widen the type's
   `allowed` list in `docs/registers/subject-vocabulary.json` and bump the
   policy's minor version.

**Quotable fix.** Paste this into a review comment:

> **GHFM0016 (subject-outside-policy).** This document type's subject policy
> does not allow that subject. Use a concept from the type's `allowed` list,
> replace a keyword in a closed type with the concept it means, or widen the
> policy in `docs/registers/subject-vocabulary.json`.

## Enforcement

Default severity is `warning`. A type's policy may set its `severity` to
`info`, `warning` or `error`, which applies to this rule and GHFM0017 for
that type; `info` is reported at SARIF level `note`. The registry records the
rule as enforcement phase B. This rule postdates the front-matter standards
spec (design-038) section 6.2 phase listing.
